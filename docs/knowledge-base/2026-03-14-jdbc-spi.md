# 知识点沉淀 - 2026-03-14

## 📖 主题：JDBC DriverManager 与 SPI 机制深度解析

在阅读 MyBatis 源码并研究数据库连接初始化时，深入分析了 `java.sql.DriverManager` 的驱动加载机制。

### 1. DriverManager.getDrivers() 核心逻辑
`DriverManager` 在类加载时会通过 `loadInitialDrivers()` 方法初始化驱动。它不再依赖于手动执行 `Class.forName("...")`，而是利用了 Java 的 **SPI (Service Provider Interface)** 机制。

### 2. ServiceLoader 与 SPI
- **机制**：在资源目录 `META-INF/services/` 下创建一个以接口全限定名为命名的文件（如 `java.sql.Driver`），文件内容为实现类的全限定名。
- **加载**：`DriverManager` 内部调用 `ServiceLoader.load(Driver.class)`。`ServiceLoader` 会扫描类路径下所有符合规范的 jar 包并实例化这些驱动类。

### 3. 打破双亲委派机制 (TCCL)
这是理解 Java 类加载器的核心难点：
- **矛盾点**：`DriverManager` 是由 **Platform ClassLoader** 加载的，而具体的数据库驱动（如 `com.mysql.cj.jdbc.Driver`）通常位于应用的 `classpath` 下，由 **App ClassLoader** 加载。
- **规则限制**：根据双亲委派模型，父类加载器加载的类无法直接引用子类加载器加载的类。
- **解决方案**：`ServiceLoader` 内部通过 `Thread.currentThread().getContextClassLoader()` 获取 **线程上下文类加载器 (TCCL)**。
    - 默认情况下，TCCL 指向的是 **App ClassLoader**。
    - 这样，位于 **java.sql 模块**（JDK 9 之前位于 `rt.jar`）中的 `DriverManager` 就能通过 TCCL “逆向”加载到应用层的驱动类，从而打破了严格的双亲委派层级。

### 4. 驱动类的反射加载
当 `ServiceLoader` 迭代驱动时，它最终会通过反射（`Class.forName(driverName, true, loader)`）来加载并实例化驱动。在驱动类被加载时，其内部的 `static` 静态代码块会自动执行，将自身注册到 `DriverManager` 中：
```java
static {
    try {
        java.sql.DriverManager.registerDriver(new Driver());
    } catch (SQLException E) {
        throw new RuntimeException("Can't register driver!");
    }
}
```

### 5. 总结与思考
- **SPI 的价值**：解耦了接口定义与具体实现，使得框架具有极强的扩展性。
- **类加载器的灵活性**：打破双亲委派并非“破坏”，而是为了解决跨层级类加载的实际工程问题。
